# cleanup-prd

마무리 단계의 절차다. PR을 머지하고 3개월이 지나면 PRD 폴더를 정리한다. 통합 PRD만 `docs/prd/` 바로 아래에 남기고, 테스트 목록·원본 문서·Figma 캐시가 든 폴더는 삭제한다. 테스트 목록의 내용은 이미 PR 설명에 남아 있다.

커밋 규칙은 `docs/policy/tdd.md`를 따른다.

## 입력

- 정리할 PRD 폴더: `docs/prd/[<Jira 티켓 번호>] <소문자 영어 PRD 제목>/` (저장소 루트 기준)
- 통합 PRD 상단 정보의 `구현 PR` 줄에 적힌 PR 번호들. 줄이 없거나 `없음`이면 사용자에게 PR 번호를 묻는다.

## 시작 전 확인

- 커밋하지 않은 변경이 있으면 시작하지 않고 보고한다.
- PRD 폴더가 없으면 보고한다.
- PRD 폴더에 통합 PRD(`PRD-<Jira 티켓 번호>-<영어 제목>.md`)가 없으면 보고하고 멈춘다.
- `구현 PR`의 번호마다 `gh pr view <PR 번호> --json state,mergedAt`로 머지 여부와 머지일을 확인한다. `OPEN` 상태인 PR이 하나라도 있으면 그 번호를 보고하고 멈춘다. 머지되지 않고 `CLOSED`된 PR은 제외하고, 제외한 번호를 보고한다. 머지된 PR이 하나도 없으면 보고하고 멈춘다.
- 모두 머지됐으면 머지일이 가장 늦은 PR을 기준으로 3개월이 지났는지 확인한다. 지나지 않았으면 기준 PR 번호, 머지일, 정리 가능한 날짜를 보고하고 멈춘다.

## 절차

1. `origin/develop`을 기준으로 새 브랜치 `docs/<Jira 티켓 번호>-prd-cleanup`을 만든다. 예: `docs/KD3-636-prd-cleanup`. 이미 있는 브랜치 위에서 하지 않는다.
2. 통합 PRD를 `docs/prd/` 바로 아래로 옮긴다. 파일 이름은 바꾸지 않는다.
3. 통합 PRD 상단 정보의 `문서 원본 보관`, `Figma 캐시 보관` 줄을 `보관 안 함 (<오늘 날짜>에 삭제)`로 바꾼다. 본문의 `./original/`, `./figma/` 상대 링크는 고치지 않는다. 끊어진 링크가 있으면 보고에 적는다.
4. PRD 폴더와 그 안에 남은 모든 파일(`test-list.md`, `original/`, `figma/` 등)을 삭제한다.
5. `docs: PRD 폴더 정리 (<Jira 티켓 번호>)`로 커밋한다.
6. 남긴 파일 경로, 삭제한 항목, 끊어진 링크, 브랜치 이름을 보고한다.

## 하지 않는 것

- 통합 PRD 외 다른 PRD 폴더나 파일을 수정하거나 삭제하지 않는다.
- 푸시와 PR 생성은 사용자가 요청할 때만 한다.
- 승인, 머지를 하지 않는다.

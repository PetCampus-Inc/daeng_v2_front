# Figma 접근과 호출 관리

Figma를 읽는 목적과 무관하게 **캐시를 먼저 확인하고, 새 호출은 구조 1회와 필요한 이미지 1회 안에서 끝낸다.** 호출 횟수를 줄이기 위해 필요한 정보를 생략하지는 말고, 섹션과 여러 노드를 한 요청으로 묶는다.

## 요청 전

1. 링크에서 파일 키와 `node-id`를 확인한다. 선택한 요소 링크가 아니라 파일 링크만 있으면 필요한 노드를 사용자에게 확인한다.
2. 현재 프로젝트의 저장 자료를 먼저 찾는다. 위에 있는 것부터 본다.
   - `docs/prd/[<Jira 티켓 번호>] <제목>/figma/` (PRD 폴더의 Figma 캐시)
   - 사용자가 직접 제공한 JSON·PNG·SVG
3. 필요한 정보가 캐시에 있으면 API나 MCP를 다시 호출하지 않는다.

## 새로 읽어야 할 때

- 사용자가 섹션이나 프레임 URL을 주고 그 범위를 읽어 달라고 하면 **REST API만 사용한다.** 코드 구현 요청이어도 이 기준은 같다.
- 섹션 노드 구조는 REST로 **1회** 조회한다. 링크가 여러 개면 `ids=a,b,c`처럼 묶고 응답은 해당 PRD 폴더의 `figma/`에 저장한다. PRD 폴더가 없으면 저장 위치를 사용자에게 묻는다.
- 렌더링 이미지가 꼭 필요하고 캐시에 없을 때만 필요한 노드를 묶어 REST 이미지 API를 **1회** 호출한다.
- MCP는 일반 선택지가 아니라 다음 예외에서만 사용한다.
  - 사용자가 URL 대신 Figma 데스크톱의 현재 선택 항목을 읽어 달라고 함
  - 사용자가 Code Connect 매핑이나 선택 항목에 연결된 변수·스타일 이름을 명시적으로 요청함
  - 사용자가 MCP 사용을 직접 요청함
  - REST API의 월간 무료 호출 한도를 모두 사용했지만 Figma MCP 읽기 한도는 남아 있음
- REST로 구조·문구·크기·이미지를 읽었다면 코드 구현을 위해 MCP를 추가 호출하지 않는다.
- REST 월간 한도 소진이 확인되면 REST를 재시도하지 않고 MCP로 전환한다. MCP에서도 제한 오류가 나면 추가 우회를 시도하지 않고 중단해 알린다.
- REST가 권한·인증 문제로 실패했는데 MCP로는 접근할 수 있으면, 추가 호출 전에 실패 원인과 MCP 전환을 알리고 확인받는다. 두 방식을 반복해서 오가지 않는다.
- 구조 1회와 이미지 1회를 넘어서는 호출이 필요하면 이유와 예상 추가 횟수를 먼저 사용자에게 알리고 확인받는다.

## 토큰과 실패 처리

- 개인 토큰은 환경 변수 `FIGMA_TOKEN`에서 읽고 값을 출력하거나 로그·파일·대화에 남기지 않는다.
- 로컬 셸이 환경 변수를 아직 읽지 못했다면 값 자체를 출력하지 않는 방식으로 셸 설정을 불러온다.
- `429`가 발생하면 `Retry-After`와 한도 유형을 확인한다. 일시 제한이면 사용자에게 재사용 가능 시점을 알리고 자동 재시도하지 않는다. 월간 한도 소진이면 위 규칙에 따라 MCP로 전환한다.
- 권한이 없는 팀 파일이면 우회 호출을 반복하지 않는다. 접근 가능한 개인 사본이나 필요한 PNG·SVG 내보내기를 요청한다.
- 작업을 마치면 실제로 사용한 Figma 요청 횟수를 보고한다.

## 책임 경계

이 스킬은 Figma 데이터 접근과 캐시만 담당한다. Figma를 코드로 구현하고 크기·간격을 검증하는 절차는 AGENTS.md의 단계별 스킬 표에서 Figma 구현에 해당하는 스킬이 담당한다.

# PRD 차이와 질문 해결

PRD 통합 단계가 근거 대조와 차단 분류를 마친 통합 PRD를 입력으로 받는다. 남은 사용자 결정을 하나씩 확인하고 본문에 반영한다.

## 1. 인계받은 질문 확인

- 통합 PRD의 Open Questions와 `확인이 필요한 차이`에 남은 차단 항목, 질문 근거, 선택지별 영향, 본문 위치를 확인한다. 현재 브랜치·변경사항·작업 소유자를 확인하고 다른 작업자의 변경을 보존한다.
- 질문에 필요한 근거 또는 영향이 빠져 있다면 사용자에게 추측해서 묻지 않고 PRD 통합 단계에서 해당 항목을 보완한다. 이 단계에서 전체 DIFF·OQ를 다시 조사하지 않는다.

## 2. 사용자에게 하나씩 확인

- 인계받은 차단 결정 중 첫 항목 하나만 쉬운 말로 질문한다. 왜 사용자 결정이 필요한지, 선택지마다 실제 구현·TC에 어떤 영향이 있는지, 추천안과 근거를 함께 설명한다. 가능한 경우 클릭 선택 UI를 사용한다.
- 답을 받기 전에는 임의로 확정하거나 다음 질문·TC·제품 구현으로 넘어가지 않는다. `진행해` 같은 일반 요청을 결정의 답으로 해석하지 않는다.
- 답변이 기존 인계 근거를 뒤집거나 새로운 원본 충돌을 드러내면 해당 항목만 PRD 통합 단계에서 다시 정리한 뒤 질문한다.

## 3. 답변 반영

PRD를 수정하기 전 임시 디렉터리에 번호가 붙은 백업을 만든다.

- 답이 확정되면 본문의 `(OQ-…)` 표시를 제거하고 결정 내용을 반영한다. Open Questions의 행은 접힌 `확정된 질문` 표로 옮겨 절대 날짜, 사용자 답변, 본문 반영 위치를 적는다.
- 답을 반영해 새 상태나 경로가 생기면(예: 찾지 못함, 조회 실패) 그 상태가 화면에 어떻게 보이는지까지 정해졌는지 확인한다. 정해지지 않았으면 다음 질문으로 넘어가기 전에 이어서 묻는다.
- 일부만 답했으면 Open Questions에 유지하고 답한 부분과 남은 질문을 분리한다. 기존 결정을 번복하면 이전 결정의 취소 날짜와 새 결정을 함께 기록한다.
- DIFF가 확정되면 양쪽 원문과 확정 기준, 본문 위치를 보존해 `확정된 차이`로 옮긴다. 실제로 사용자에게 질문한 결정만 `확정된 질문`에도 기록한다.
- PRD의 본문과 Open Questions 장이 서로 다른 상태를 말하지 않도록 같은 작업에서 갱신한다.

## 4. 완료 기준과 인계

- 답변한 DIFF·OQ가 본문의 단일 구현 기준에 연결됐는지, 확정된 항목이 Open Questions와 `확인이 필요한 차이`에 남아 있지 않은지 확인한다. 검증이 성공하면 임시 백업을 삭제하고 실패하면 보존 위치와 문제를 보고한다.
- 현재 범위의 차단 결정이 모두 해결됐으면 확정된 PRD 경로, 보류·제외 범위, API 계약 근거, TC 작성 가능 상태를 다음 단계(AGENTS.md의 단계별 스킬 표 기준)에 넘긴다.
- 차단 결정이 남으면 다음 질문 하나를 제시하고 답을 기다린다. 그동안 확정 TC나 제품 구현을 시작하지 않는다.

## 하지 말 것

- 원본을 수정하거나, 원본에서 확인된 사실을 사용자 답변처럼 기록하지 않는다.
- 이 단계에서 TC, 제품 코드, 테스트 파일, Orval 생성물을 만들지 않는다.

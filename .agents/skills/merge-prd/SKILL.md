# Merge PRD

여러 원본을 추적 가능한 개발 기준 PRD 하나로 합친다. Figma가 있으면 항상 본문 기준으로 삼고, 원본 간 차이·단독 내용·미확정 기술 사항을 숨기지 않는다.

## 시작 전에 확정할 것

1. 원본을 끝까지 읽고 파일명, 상태, 편집일, 링크를 기록한다. 원본은 수정하지 않는다.
2. 통합 PRD는 `docs/prd/` 아래에 저장한다.
3. 결과를 `docs/prd/[<Jira 티켓 번호>] <소문자 영어 PRD 제목>/` 폴더 하나로 묶는다. 예: `docs/prd/[KD3-636] pass-registration/`. 본문은 이 폴더의 `PRD.md`, 문서 원본은 `original/`, Figma 캐시는 `figma/`에 둔다. Jira 티켓 번호나 PRD 제목을 알 수 없으면 사용자에게 묻는다.
4. Figma가 없으면 어떤 원본을 본문 기준으로 삼을지 선택받는다. 가능한 경우 구조화된 선택 UI를 쓰고, 없으면 짧은 번호 선택지를 제시한다. 편집일만 보고 자동 결정하지 않는다.

## 원본 보존

- PDF와 Markdown 원본은 내용과 파일명을 바꾸지 않고 PRD 폴더의 `original/`에 복사한다.
- Figma 링크가 있으면 AGENTS.md의 단계별 스킬 표에서 Figma 조회에 해당하는 스킬을 읽고 따른다. Description과 관련 화면을 포함한 **상위 섹션 링크 하나**를 입력 범위로 사용한다.
- 기존 캐시를 먼저 찾고, 사용자가 최신화나 다시 읽기를 요청하지 않았다면 재호출하지 않는다.
- 새 조회가 필요하면 섹션 구조·텍스트·하위 프레임 ID를 한 요청으로 받고, 화면 이미지는 필요한 프레임 ID를 묶어 한 요청으로 받는다. 구조 1회와 이미지 1회를 넘기기 전에는 사용자에게 이유와 예상 횟수를 알리고 확인받는다.
- Figma 원본 JSON, 추출 텍스트, 화면 이미지를 PRD 폴더의 `figma/`에 보존한다. 인증 토큰과 서명된 임시 URL은 문서나 로그에 남기지 않는다.
- Figma를 실제로 새로 조회했다면 완료 보고에 호출 횟수를 포함한다.

## 통합 판단

| 경우 | 본문 | 기록 |
|---|---|---|
| 원본들이 같은 내용을 말함 | 표시 없이 반영 | 없음 |
| PDF·문서와 Figma가 충돌함 | Figma를 확정 기준으로 반영 | `DIFF-1`부터 차이표에 양쪽 원문 기록 |
| PDF·문서에만 있고 내용이 명확하며 다른 원본과 충돌하지 않음 | 확정 요구사항으로 반영하고 `(PRD 단독)` 표시 | OQ로 등록하지 않음 |
| Figma에만 있고 내용이 명확하며 다른 원본과 충돌하지 않음 | 확정 요구사항으로 반영하고 `(Figma 단독)` 표시 | OQ로 등록하지 않음 |
| PDF·문서 단독 내용이 모호하거나 확인이 필요함 | 확인 전 기준을 명시하고 `(OQ-Pn)` 표시 | OQ-P에 등록 |
| Figma 단독 내용 또는 Figma 내부 표현이 모호하거나 확인이 필요함 | 확인 전 기준을 명시하고 `(OQ-Fn)` 표시 | OQ-F에 등록 |
| 클라이언트 확인 필요 | 확인 전 기준을 명시하고 `(OQ-Cn)` 표시 | OQ-C에 등록 |
| 서버 확인 필요 | 확인 전 기준을 명시하고 `(OQ-Sn)` 표시 | OQ-S에 등록 |
| 원본에 없는 추론 | `(내 추론)` 표시 | 중요한 결정이면 담당 OQ에도 등록 |

- 차이는 OQ로 중복 등록하지 않는다. Figma를 본문 기준으로 적용하고 `DIFF-n`에만 남긴다.
- `(PRD 단독)`과 `(Figma 단독)`은 출처 표시이며 미확정 표시가 아니다. 별도 ID나 Open Questions 행을 만들지 않는다.
- 단독 원본의 문구가 명확해도 API 계약·클라이언트 구현 방식이 비어 있으면 요구사항은 단독 표시로 확정하고, 기술 계약만 OQ-C/S로 분리해 연결한다.
- 단독 내용 자체가 모호하거나 원본 내부에서 충돌해 기대 결과를 고정할 수 있을 때만 OQ-P/F로 등록한다. 질문은 담당자가 바로 결정할 수 있게 쓴다.
- OQ는 원본의 실제 공백이나 충돌을 기록하는 것이지, 에이전트가 아직 조사하지 않은 내용을 기록하는 곳이 아니다. OQ-C/S를 만들기 전에 관련 원본·정책·코드·OpenAPI/Swagger에서 확인 가능한지 먼저 조사한다.
- 조사로 확인한 사실은 본문과 출처에 직접 반영한다. 현재 범위의 기대 결과를 바꾸지 않는 컴포넌트 선택, 서버 내부 구현 방법, 범위 밖 기능의 기술 계약은 통합 PRD의 OQ로 만들지 않는다.
- 답에 따라 이번 범위, UI 동작·문구·상태, 검증 규칙, 이동 경로, 데이터 구조, API 계약 또는 TC 기대 결과가 바뀌는 미해결 항목만 차단 OQ로 분류한다. 보류·제외해도 확정된 결과가 달라지지 않는 사항은 미확정 제품 OQ로 두지 않는다.
- 사용자 확인이 필요한 각 DIFF·OQ에는 확인한 근거와 남은 선택지의 실제 영향을 기록해 다음 단계에서 추가 근거 조사 없이 질문할 수 있게 한다.
- ID는 종류별로 1부터 증가시키고 재사용하지 않는다.
- UI 문구와 문장부호는 본문, 차이표, OQ 모두 원문 그대로 보존하고 백틱으로 감싼다.

## 문서 작성

PRD를 만들거나 구조를 변경할 때 [references/template.md](references/template.md)를 읽고 표 열과 핵심 장을 그대로 사용한다.

- 항상 포함: 이 문서를 읽는 법, 원본, 개요, 범위, PDF·문서와 Figma의 차이, Open Questions, 구현할 때 놓치기 쉬운 점
- 원본에 있을 때만 포함: 사용자 흐름, 공통 정책, 상태, 데이터 항목, 화면 명세, 알림
- 화면 명세의 순서와 번호는 Figma를 따른다. Figma가 없으면 사용자가 고른 기준 원본을 따른다.
- 각 절에 출처 위치를 적어 원본으로 되돌아갈 수 있게 한다.
- 숫자, 경계값, 오류·빈 상태·권한 없음, 제외 범위를 원본 그대로 옮긴다. 없는 내용을 완성된 정책처럼 만들지 않는다.
- 9장의 DIFF는 `확인이 필요한 차이`와 접힌 `확정된 차이`로 나눈다. 우선순위 규칙이나 사용자 결정으로 본문의 단일 구현 기준이 정해지면 양쪽 원문·확정 기준·본문 위치를 보존한 채 `확정된 차이`로 옮긴다. 아직 결과를 고를 수 없는 DIFF만 `확인이 필요한 차이`에 둔다.

## 코드베이스 조사

작업공간에 구현 코드가 있으면 읽기 전용으로 다음을 확인하고 마지막 장에 근거와 함께 적는다.

- 기존 진입점과 외부 링크
- 재사용할 컴포넌트와 공통 정책
- 내비게이션·브리지·권한 제약
- 화면 사이에 전달해야 하는 값과 이탈·중복 요청 처리

코드로 확인할 수 없고 답에 따라 현재 범위의 요구사항·API 계약·TC 기대 결과가 달라지는 내용만 OQ-C 또는 OQ-S로 남긴다. 서버 내부 구현 방식이나 범위 밖 기술 사항은 OQ로 만들지 않는다.

## 다음 단계로 인계

- 통합 PRD에는 우선순위 규칙으로 확정된 DIFF와 근거 대조 후에도 남은 차단 DIFF·OQ를 구분한다. 사용자에게 질문하고 답을 반영하는 작업은 결정 확인 단계가 담당한다.
- 완료 보고에 통합 PRD 경로, 사용한 원본·Figma 캐시 경로, 확정된 차이와 확인이 필요한 차이, 답이 필요한 OQ-P/F/C/S 개수, 첫 차단 결정과 근거를 적는다.
- 이 결과는 다음 단계의 입력이다. PRD 통합만 요청받았다면 여기서 종료한다. 구현까지 요청받았다면 결정 확인 단계로 이어서 남은 사용자 결정을 하나씩 확인한다.

## 수정 안전성과 검증

통합 PRD를 만들거나 통합 과정에서 수정하기 전 임시 디렉터리에 번호가 붙은 백업을 만든다.

완료 전에 다음을 모두 확인한다.

1. 본문의 모든 `OQ-*`가 Open Questions 표에 있고 아직 답이 없는 OQ도 본문에 연결되어 있다.
2. 모든 `DIFF-*`가 본문과 차이표에서 서로 연결되고, 단일 구현 기준이 정해진 항목은 `확정된 차이`에 있으며 미확정 항목만 `확인이 필요한 차이`에 있다.
3. 모든 `(PRD 단독)`·`(Figma 단독)` 요구사항이 표시한 원본에 실제로 있고 다른 원본과 충돌하지 않는다.
4. 원본의 `확인 필요`, `미정`, `TBD`, `추후`가 빠지지 않았다.
5. 원본 UI 문구와 문장부호가 변경되지 않았다.
6. `original/`에 사용한 문서 원본이, `figma/`에 사용한 Figma 캐시가 보존됐다.
7. 읽는 법, 원본, 정리일, 기준 원본이 기록됐다.

검증에 성공하면 같은 작업 안에서 임시 백업을 삭제한다. 실패하면 백업을 유지하고 위치와 실패 항목을 보고한다. 완료 보고에는 `DIFF`, `PRD 단독`, `Figma 단독`, `OQ-P/F/C/S` 개수와 우선 답변이 필요한 블로커를 함께 적는다.

## 하지 말 것

- 원본 파일을 수정하거나 원문을 조용히 다듬지 않는다.
- Figma가 있는데 다른 문서를 우선하지 않는다.
- 명확하고 비충돌인 단독 요구사항을 출처 표시 없이 일반 확정 요구사항처럼 적지 않는다.
- 캐시가 있는데 Figma를 다시 호출하지 않는다.
- 사용자 결정, 계정·키·외부 서비스 값을 추측하지 않는다.
- 진행 현황이나 계속 변하는 파일·TC 개수를 개발 기준 PRD에 섞지 않는다.

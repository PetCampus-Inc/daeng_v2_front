# 개발 기준 PRD 템플릿

`merge-prd`가 새 문서를 만들거나 기존 문서 구조를 바꿀 때 사용한다. 해당 기능에 없는 조건부 장은 생략하되 핵심 장과 표 열은 유지한다.

```markdown
# [티켓] 기능명 — 개발 기준 PRD

- 정리일: YYYY-MM-DD — (통합하거나 수정한 원본)
- 기준 원본: Figma / (Figma가 없을 때 사용자가 선택한 원본)
- 문서 원본 보관: `./original/`
- Figma 캐시 보관: `./figma/`
- 구현 PR: 없음 (PR 생성 단계에서 번호를 추가한다)

## 이 문서를 읽는 법

| 표시 | 뜻 | 기록 위치 |
|---|---|---|
| 표시 없음 | 여러 원본이 같은 내용을 말한다 | - |
| `(PRD 단독)` | PDF·문서에만 있지만 명확하고 비충돌인 확정 요구사항 | 본문과 원본 위치 |
| `(Figma 단독)` | Figma에만 있지만 명확하고 비충돌인 확정 요구사항 | 본문과 Figma 위치 |
| `(DIFF-n)` | 문서와 Figma가 다르며 본문은 Figma를 따른다 | 9. PDF·문서와 Figma의 차이 |
| `(OQ-Pn)` | PDF·문서 내용 중 모호하거나 확인이 필요한 질문 | 10. Open Questions |
| `(OQ-Fn)` | Figma 내용 중 모호하거나 내부 확인이 필요한 질문 | 10. Open Questions |
| `(OQ-Cn)` | 클라이언트에서 확인할 내용 | 10. Open Questions |
| `(OQ-Sn)` | 서버에서 확인할 내용 | 10. Open Questions |
| `(내 추론)` | 원본에 없고 정리 과정에서 추론한 내용 | 본문과 필요 시 OQ |
```

## 작성 규칙

- 사용하지 않는 예시 행은 최종 문서에서 삭제한다.
- 명확하고 비충돌인 단독 요구사항은 OQ 표에 넣지 않고 본문에 `(PRD 단독)` 또는 `(Figma 단독)`으로 표시한다.
- OQ 질문은 한 행에 하나만 둔다. 질문이 나뉘면 새 ID를 발급한다.
- 원문 열은 요약하지 않는다. 문구와 문장부호를 그대로 옮긴다.
- 코드에서 확인한 사실에는 파일 경로와 확인 날짜를 적는다.
- 미확인 기술 주장은 `추정` 또는 `미확인`으로 표시하고 OQ-C/S로 연결한다.

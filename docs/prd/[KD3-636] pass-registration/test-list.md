# 테스트 목록: [KD3-636] 이용권 등록 (PRD: pass-registration)

## 기능: 마이페이지 이용권 관리 진입 (PRD 2.1, 7장 01)
- [x] [컴포넌트] 원장 마이페이지의 `이용권 관리` 메뉴를 누르면 `/mypage/pass-templates`로 이동한다 (신규)
- [생략] `유치원 관리`에 `이용권 관리`와 `자주 사용하는 이용권을 관리 할 수 있어요.`를 표시한다 — 사유: 로직 없이 정적 문구만 보여 줌

## 기능: 원장 전용 접근 (PRD 3장)
- [x] [컴포넌트] 원장이 아닌 사용자가 목록 화면(`/mypage/pass-templates`)에 들어오면 `/mypage`로 이동한다 (신규)
- [x] [컴포넌트] 원장이 아닌 사용자가 등록 화면(`/mypage/pass-templates/create`)에 들어오면 `/mypage`로 이동한다 (신규)
- [x] [컴포넌트] 원장이 아닌 사용자가 수정 화면(`/mypage/pass-templates/[id]`)에 들어오면 `/mypage`로 이동한다 (신규)

## 기능: 목록 보조 정보 표시 (PRD 4.1, 6.1)
- [x] [유닛] 유효기간이 없으면 `만료 없음`, 일 단위면 `n일`, 개월 단위면 `n개월`로 바꾼다 (신규)
- [x] [유닛] 만료 없음 템플릿은 보조 정보를 `{n}회 · 만료 없음`으로 만든다 (신규)
- [x] [유닛] 서버 응답에 기간이 있으면 보조 정보를 `{n}회 · {기간}`으로 만든다 (신규)

## 기능: 목록 조회 화면 (PRD 4.1, 4.6, 5장 S-01)
- [x] [컴포넌트] 템플릿이 있으면 서버가 준 순서 그대로 카드를 보여 준다 (신규)
- [x] [컴포넌트] 템플릿이 0개면 `아직 등록된 이용권이 없어요`와 `자주 사용하는 이용권을 등록할 수 있어요.`를 보여 준다 (신규)
- [x] [컴포넌트] 목록 조회가 250ms 넘게 걸리면 Header를 유지한 채 콘텐츠 영역에 Spinner를 보여 준다 (신규)
- [x] [컴포넌트] 목록 조회가 250ms 안에 끝나면 Spinner를 보여 주지 않는다 (신규)
- [x] [컴포넌트] 목록 조회가 실패하면 빈 상태 대신 `정보를 불러오지 못했어요`, `잠시 후 다시 시도해 주세요.`, `다시 시도하기`를 보여 준다 (신규)
- [x] [컴포넌트] 조회 실패 후 `다시 시도하기`를 누르면 목록을 다시 불러와 보여 준다 (신규)
- [x] [컴포넌트] 재조회 중에는 `다시 시도하기`를 다시 눌러도 요청이 추가로 나가지 않는다 (신규)
- [x] [컴포넌트] 조회 실패 후 사용자가 `다시 시도하기`를 누르기 전에는 다시 요청하지 않는다 (신규)
- [x] [컴포넌트] 카드를 누르면 해당 템플릿의 수정 화면(`/mypage/pass-templates/[id]`)으로 이동한다 (신규)
- [x] [컴포넌트] 목록 화면과 빈 상태 화면에서 `이용권 등록하기`를 누르면 등록 화면으로 이동한다 (신규)
- [생략] 이름이 한 줄을 넘으면 `…`로 줄인다 — 사유: 스타일
- [생략] `이용권 등록하기` 버튼을 Safe Area 위에 고정하고 마지막 카드가 가리지 않게 한다 — 사유: 레이아웃
- [생략] 유치원마다 `체험 등원(1회권)` 기본 템플릿을 만들고 맨 위에 둔다 — 사유: 서버가 생성·정렬하고 프론트는 받은 목록을 그대로 보여 줌
- [생략] 템플릿 개수 제한이 없다 — 사유: 프론트에 제한 로직이 없음

## 기능: 이름 입력 (PRD 4.2, 4.6)
- [x] [유닛] 이름의 앞뒤 공백을 지우고 연속 공백을 하나로 합친다 (신규)
- [x] [유닛] 공백만 있는 이름은 유효하지 않다 (신규)
- [x] [컴포넌트] 이름을 50자 넘게 입력하면 51번째 글자부터 입력되지 않는다 (신규)
- [x] [컴포넌트] 이름을 입력하면 글자 수가 `n/50`으로 바뀐다 (신규)

## 기능: 충전 횟수 입력 (PRD 4.3, 4.6)
- [x] [유닛] 충전 횟수는 1~1000 정수만 허용하고 0, 1001, 소수는 거부한다 (신규)
- [x] [유닛] 충전 횟수에 `1e3`, `0x10`, 공백이 섞인 값, 빈 값이 들어오면 거부한다 (신규)
- [x] [컴포넌트] 범위를 벗어난 충전 횟수를 입력하고 필드를 벗어나면 `충전 횟수는 1~1000회 사이로 입력해 주세요.`가 보이고 CTA가 비활성화된다 (신규)
- [x] [컴포넌트] 충전 횟수 오류가 보이는 상태에서 올바른 값으로 고치면 오류가 바로 사라진다 (신규)
- [생략] 충전 횟수 필드는 숫자 키패드를 띄운다 — 사유: 입력 속성만 지정하고 로직 없음

## 기능: 유효기간 선택 (PRD 4.4)
- [x] [유닛] 직접 입력 값은 1~99 정수일 때만 유효하고 0, 100은 유효하지 않다 (신규)
- [x] [유닛] 만료 없음을 고르면 유효기간 없이 등록 요청을 보낸다 (신규)
- [x] [유닛] 기간 칩(1·3·6·12개월)과 직접 입력 값을 숫자와 단위(일·개월)로 보낸다 (신규)
- [x] [컴포넌트] 신규 등록 화면에 처음 들어오면 아무 기간 칩도 선택돼 있지 않고 직접 입력 필드도 보이지 않는다 (신규)
- [x] [컴포넌트] `직접 입력`을 누르면 숫자 필드와 `일`·`개월` 선택이 보인다 (신규)
- [x] [컴포넌트] 직접 입력 상태에서 다른 기간 칩을 누르면 직접 입력 필드가 사라진다 (신규)

## 기능: 등록 (PRD 4.5, 4.6, 5장 S-02 신규, 7장 04~09·17·18)
- [x] [컴포넌트] 이름·충전 횟수·유효기간이 모두 유효할 때만 `등록하기`가 활성화된다 (신규)
- [x] [컴포넌트] `등록하기`를 누르면 이름 앞뒤 공백과 연속 공백을 정리한 값으로 등록 요청을 보낸다 (신규)
- [x] [컴포넌트] 등록 요청 중에는 `등록하기`가 비활성화돼 다시 눌러도 요청이 한 번만 나간다 (신규)
- [x] [컴포넌트] 등록 요청이 250ms 넘게 걸리면 CTA에 Spinner가 보인다 (신규)
- [x] [컴포넌트] 등록에 성공하면 목록으로 돌아가 `이용권이 등록됐어요` 토스트를 보여 준다 (신규)
- [x] [컴포넌트] 서버가 `TICKET_TEMPLATE-409-1`을 주면 이름 아래 `이미 같은 이름의 템플릿이 있어요.`가 보이고 입력값은 유지되며 CTA가 비활성화된다 (신규)
- [x] [컴포넌트] 이름 중복 오류가 보이는 상태에서 이름을 바꾸면 오류가 사라지고 CTA가 다시 활성화된다 (신규)
- [x] [컴포넌트] 그 밖의 이유로 등록에 실패하면 화면과 입력값을 유지하고 `이용권을 등록하지 못했어요` 토스트를 보여 준 뒤 CTA를 다시 활성화한다 (신규)
- [생략] 헤더 `이용권 관리`, 이름 placeholder `이름을 입력하세요.`, CTA 문구 `등록하기`를 표시한다 — 사유: 정적 문구

## 기능: 수정 (PRD 4.5, 6.1, 5장 S-02 수정, 7장 10·11·14)
- [x] [유닛] 저장된 유효기간이 칩 값(만료 없음·1·3·6·12개월)과 같으면 그 칩을, 아니면(예: 80일, 30일) 직접 입력을 선택한 상태로 바꾼다 (신규)
- [x] [유닛] URL의 템플릿 ID가 목록에 없거나 정수가 아니면(`abc`, `1e3`, `0x10`, 공백) 찾지 못한 것으로 판단한다 (신규)
- [x] [컴포넌트] 수정 화면에 들어오면 헤더에 템플릿 이름이, 입력란에 기존 값이, 오른쪽 위에 삭제 아이콘이 보인다 (신규)
- [x] [컴포넌트] 기존 값에서 바뀐 것이 없으면 CTA가 비활성화돼 있다 (신규)
- [x] [컴포넌트] 값을 바꿨다가 원래 값으로 되돌리면 CTA가 다시 비활성화된다 (신규)
- [x] [컴포넌트] 유효한 값으로 바꾸면 CTA가 활성화되고, 바뀐 값이 유효하지 않으면 비활성화된다 (신규)
- [x] [컴포넌트] 수정 화면에서 템플릿 정보를 불러오지 못하면 Header를 유지한 채 `정보를 불러오지 못했어요`, `잠시 후 다시 시도해 주세요.`, `다시 시도하기`를 보여 준다 (신규)
- [x] [컴포넌트] 목록에 해당 ID의 템플릿이 없으면 이용권 목록 화면으로 이동하고 `이용권을 찾을 수 없어요` 토스트를 보여 준다 (신규)
- [x] [컴포넌트] 저장 요청 중에는 CTA가 비활성화돼 다시 눌러도 요청이 한 번만 나간다 (신규)
- [x] [컴포넌트] 저장에 성공하면 목록으로 돌아가 `이용권을 저장했어요` 토스트를 보여 준다 (신규)
- [x] [컴포넌트] 수정 중 서버가 `TICKET_TEMPLATE-409-1`을 주면 이름 아래 중복 문구를 보여 주고 입력값을 유지한다 (신규)
- [x] [컴포넌트] 그 밖의 이유로 저장에 실패하면 화면과 입력값을 유지하고 `이용권을 저장하지 못했어요` 토스트를 보여 준 뒤 CTA를 다시 활성화한다 (신규)

## 기능: 삭제 (PRD 4.5, 5장 S-03, 7장 12·13·15)
- [x] [컴포넌트] 삭제 아이콘을 누르면 `이용권을 삭제할까요?`, `이미 충전한 이용권은 그대로 사용할 수 있어요`, `닫기`, `삭제하기` 모달이 보인다 (신규)
- [x] [컴포넌트] 모달에서 `닫기`를 누르면 모달만 닫히고 수정 화면과 입력값이 그대로 남는다 (신규)
- [x] [컴포넌트] 삭제 요청 중에는 `삭제하기`를 다시 눌러도 요청이 한 번만 나간다 (신규)
- [x] [컴포넌트] 삭제에 성공하면 목록으로 돌아가 해당 항목이 빠지고 `이용권을 삭제했어요` 토스트를 보여 준다 (신규)
- [x] [컴포넌트] 마지막 남은 템플릿(기본 템플릿 포함)을 삭제하면 목록이 빈 상태로 보인다 (신규)
- [x] [컴포넌트] 삭제에 실패하면 모달을 닫고 수정 화면과 입력값을 유지하며 `이용권을 삭제하지 못했어요` 토스트를 보여 준다 (신규)

## 기능: 뒤로가기와 작성 중 이탈 (PRD 3장, 4.5)
- [x] [컴포넌트] 목록 화면에서 뒤로가기를 하면 `/mypage`로 이동한다 (신규)
- [x] [컴포넌트] 등록·수정 화면에서 바뀐 값 없이 뒤로가기를 하면 목록으로 이동한다 (신규)
- [x] [컴포넌트] 등록·수정 화면에서 값을 바꾼 뒤 뒤로가기를 하면 `이용권을 저장하지 않고 나갈까요?` 모달이 보인다 (신규)
- [x] [컴포넌트] 이탈 확인 모달에서 나가기를 고르면 저장하지 않고 목록으로 이동한다 (신규)
- [x] [컴포넌트] 이탈 확인 모달에서 계속 작성을 고르면 화면과 입력값이 그대로 남는다 (신규)
- [x] [컴포넌트] 삭제 확인 모달이 열린 상태에서 뒤로가기를 하면 모달만 닫히고 수정 화면이 남는다 (신규)
- [x] [컴포넌트] 브라우저 뒤로가기와 네이티브 뒤로가기도 상단 뒤로가기와 같은 순서(모달 닫기 → 이탈 확인 → 이전 화면)로 동작한다 (신규)

## 기능: 템플릿 스냅샷 (PRD 1장, 6장)
- [생략] 충전 시점에 템플릿 값을 개별 이용권으로 복사하고 이후 수정·삭제가 이미 충전된 이용권에 영향을 주지 않는다 — 사유: 개별 이용권 충전은 이번 범위 밖(PRD 2.2)이고 서버가 보장함

## 기능: 알림 (PRD 8장)
- [생략] 생성·수정·삭제 시 별도 푸시·문자·이메일 알림을 보내지 않는다 — 사유: 추가할 로직이 없음

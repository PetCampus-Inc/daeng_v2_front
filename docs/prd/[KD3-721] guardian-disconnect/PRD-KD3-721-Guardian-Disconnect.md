## 1. 개요

보호자가 강아지 단위로 유치원 연결을 해제하는 기존 기능에 이용권·예약 조건 검사를 추가하고, 마이페이지에 해제 진입점을 새로 둔다. 사용 가능한 이용권이나 이용이 끝나지 않은 예약이 있으면 해제할 수 없다. (원본 문서 1장)

- 배경: v4.0부터 이용권이 앱 안에서 관리되고 원생(강아지)에게 귀속된다. 원생 등록이 끝나면 남은 이용권을 쓸 수 없다. 지금 해제 기능에는 이용권·예약 확인 단계가 없어서, 이용권이 남은 채 해제되면 결제한 횟수가 사라지고 잡힌 예약은 처리할 곳이 없어진다. (PRD 단독, 원본 문서 1.2)
- 목적 (PRD 단독, 원본 문서 1.3)
  - 사용 가능한 이용권이나 다가오는 예약이 있으면 해제를 막는다.
  - 해제할 수 없을 때 이유와 해결 방법을 알려준다.
  - 마이에서 해제할 수 있게 한다. 기존 유치원 탭 진입점은 유치원 탭 개편 전까지 그대로 둔다.
  - 해제 위치와 기본 흐름은 기존 기능을 유지해 개발 범위를 줄인다.
- 보호자 자진 해제는 원장 승인 없이 즉시 해제하고 유치원에 알림을 보낸다. (PRD 단독, 원본 문서 1.2)

## 4. 공통 정책

### 4.1 연결·해제 단위

- 강아지 한 마리는 유치원 1곳에만 연결될 수 있다. 원본 문서 FR-01, Figma 2b
- 연결 해제는 강아지 단위로 한다. 여러 마리 중 한 마리만 해제할 수 있다. 원본 문서 FR-02, Figma 2a

### 4.2 해제 가능 조건

출처: Figma Description `4` 해제 불가 조건 (DIFF-3), 원본 문서 FR-03

사용 가능한 이용권과 이용이 끝나지 않은 예약이 모두 없을 때만 해제할 수 있다.

- 사용 가능한 이용권: 잔여 횟수 1회 이상이면서 유효기간이 지나지 않은 이용권. 만료 없음 이용권도 포함한다.
- 잔여 0회 또는 유효기간이 지난 이용권만 있거나 이용권이 없으면 해제할 수 있다.
- 이용 완료된 예약: 등원 또는 결석 처리된 예약. 이용 완료되지 않은 예약이 하나라도 있으면 해제할 수 없다. 서버는 상태가 `CONFIRMED`(예약 확정)인 예약만 막고 등원 완료·결석·취소는 막지 않는다. 등원은 했지만 하원 전인 예약도 막지 않는다. (백엔드 `ReservationDisconnectBlockChecker`, `origin/dev` 2026-11-09 확인)
- 당일 등원 기록이 있으면 해제할 수 없다. 두 원본에는 없는 기존 규칙이며 서버가 그대로 유지한다. 해제 가능 여부 조회에서는 `ATTENDANCE`, 해제 요청에서는 오류 코드 `SCHOOL_MEMBERSHIP-409-1`로 막는다. 앱은 기존 토스트 `오늘은 등원 기록이 있어 연결을 해제할 수 없어요`를 그대로 쓴다. (내 추론: 토스트 재사용) 당일 등원 기록과 남은 이용권·예약이 함께 있으면 당일 등원 토스트만 보여 주고 해제 불가 시트는 열지 않는다. (사용자 결정 2026-11-09)
- 해제 가능 여부와 바텀시트에 보여 줄 이용권·예약 정보는 `GET /api/v0/guardian/school/connections/{schoolPetMembershipId}/disconnect-eligibility`로 받는다. 응답 형태는 6장.

### 4.3 해제 처리

- 원장 승인 없이 바로 해제된다. 원생 등록이 종료되고 예약·새 알림장·새 앨범을 더 이상 받을 수 없다. (PRD 단독, 원본 문서 FR-05)
- 해제 전에 받은 알림장과 앨범은 읽기 전용으로 계속 볼 수 있다. 원본 문서 FR-07, Figma S-04 문구
- 해제한 유치원은 연결 이력에 계속 남는다. 등원 횟수 등 기존 정보를 그대로 보여 주고 `연결 해제` 버튼은 숨긴다. 원본 문서 FR-07-1, Figma Description `5`
- 원장이 해제할 때도 4.2 조건을 따른다. 원장 화면은 범위 밖이다. (PRD 단독, 원본 문서 FR-09)
- 해제 이력은 서비스 내부 상태 변경 이력으로 저장한다. (PRD 단독, 원본 문서 5장)

### 4.4 오류·로딩

- 다른 기기에서 이미 해제된 경우는 오류 정책의 `이미 처리된 요청` 기준을 따른다. (PRD 단독, 원본 문서 7.1) 서버는 오류 코드 `GUARDIAN_SCHOOL_CONNECTION-409-1`(`이미 해제되었거나 연결된 유치원이 아닙니다.`)을 준다. 앱은 이 `code`로 구분해 연결 이력을 다시 조회한다. (내 추론: 처리 방식)
- 로딩·중복 요청은 공통 로딩 정책을 따른다. (PRD 단독, 원본 문서 7.1) 저장소 정책: `docs/policy/loading-validation-error.md`
- 해제 조건 검사·해제 처리 중 오류가 나면 전체 오류 화면으로 바꾸지 않고 현재 화면을 유지한 채 기존 실패 토스트 `일시적 오류로 요청을 완료하지 못했어요`를 보여 준다. Figma Description `4`의 `공통 오류 화면`은 쓰지 않는다. (사용자 결정 2026-11-09, 저장소 공통 오류 정책 따름)
- 조건 검사는 통과했는데 해제 요청에서 서버가 `GUARDIAN_SCHOOL_CONNECTION-409-2`(남은 이용권·예약)로 거절하면 해제 조건을 다시 검사해 결과에 맞는 해제 불가 바텀시트(이용권이면 6a, 예약이면 6b)를 연다. 일반 실패 토스트는 보여 주지 않는다. (사용자 결정 2026-11-09)

현재 API 근거 (2026-11-09 Swagger와 백엔드 `origin/dev` 확인)

- 연결 이력: `GET /api/v0/guardian/school/connections?petId=` — `schoolPetMembershipId`, `schoolId`, `placeId`, `name`, `address`, `thumbnailImageUrl`, `status`, `connectedAt`, `disconnectedAt`, `attendedDays`, `canWriteReview`
- 연결 해제: `DELETE /api/v0/guardian/school/connections/{schoolPetMembershipId}` — 서버가 조건을 한 번 더 검사한다. 오늘 등원 기록이 있으면 `SCHOOL_MEMBERSHIP-409-1`, 남은 이용권이나 끝나지 않은 예약이 있으면 `GUARDIAN_SCHOOL_CONNECTION-409-2`, 이미 해제됐으면 `GUARDIAN_SCHOOL_CONNECTION-409-1`, 연결을 찾지 못하면 404 `GUARDIAN_SCHOOL_CONNECTION-404-1`. (백엔드 `GuardianSchoolDisconnectService`)
- 해제 가능 여부 조회: `GET /api/v0/guardian/school/connections/{schoolPetMembershipId}/disconnect-eligibility` — 백엔드 `origin/dev`에 2026-11-08 합쳐짐(#518). 공개 Swagger에는 2026-11-09 기준 아직 없다. 해제 버튼을 눌렀을 때 호출하고 응답을 캐시하지 않는다.
  - 응답: `canDisconnect`(true면 해제 요청이 성공한다), `blocks`(막는 이유 목록)
  - `blocks` 한 건: `type`(`ATTENDANCE`·`RESERVATION`·`TICKET`), `ticket`(`name`, `remainingCount`, `expiresOn` — 만료 없으면 null), `reservation`(`date`, `time` `HH:mm` — 없으면 null, `status`). `type`에 맞는 객체만 값이 있다. `ATTENDANCE`는 상세가 없다.
  - 순서·개수: 오늘 등원(`ATTENDANCE`)이 맨 앞. 예약은 등원 예정일이 가장 가까운 1건, 이용권은 만료가 이른 순으로 전부. 예약과 이용권이 모두 남으면 둘 다 `blocks`에 내려온다(예약이 앞). (백엔드 `DisconnectEligibilityService`, `origin/dev` #522, 2026-11-09 코드 확인. 서버 개발자가 수정했다고 알려 줌)
  - 이용권 기준: 잔여 1회 이상이고 만료일이 지나지 않은 이용권(만료 없음 포함). 삭제된 이용권은 제외한다.
  - `reservation.status`는 항상 `예약 확정`이다. 유치원 이름은 응답에 없다.
- 보호자용 이용권 목록·예약 목록 API는 따로 없고 위 응답으로만 받는다.

## 11. 구현할 때 놓치기 쉬운 점

이 장은 원본 요구사항이 아니라 코드베이스를 확인하며 남긴 구현 메모다. 2026-11-09에 확인했다. 확인 기준은 `origin/develop`의 `d219b429`(#775)였고, 같은 날 최신 `origin/develop`(`da7f6cf8`, #776·#777 포함)을 이 브랜치에 병합했다.

- 기존 해제 화면: 연결 이력 화면은 `route.kindergarten.connectionHistory.root`(`/kindergarten/connection-history`, `apps/knockdog/src/shared/constants/route.ts`)로 옮겨졌다. 옛 주소 `/compare/connection-history`는 새 주소로 보내 준다(`apps/knockdog/app/(stack)/compare/connection-history/page.tsx`). 보호자 `유치원` 탭은 `똑독로그` 탭(`/kindergarten`)으로 바뀌었다(#775). 화면은 `apps/knockdog/src/views/guardian-kindergarten-history-page/`. 해제 훅 `useGuardianConnectionDisconnect.tsx`, 확인 모달 `GuardianConnectionDisconnectDialog.tsx`, 카드 `GuardianConnectionHistoryCard.tsx`, 문구 `config/guardianConnectionHistoryContent.ts`를 재사용·수정 대상으로 본다. 이 폴더와 `entities/guardian-home`은 develop에서 바뀌지 않았다.
- 기존 확인 모달 본문은 `의\n유치원 소식을 더 이상 받아볼 수 없어요.`이다. 새 문구는 `받을 수 없어요.`이고 셋째 줄이 추가된다.
- 기존 흐름은 `연결 해제`를 누르면 홈을 다시 조회해 당일 등원이면 토스트로 막고, 아니면 모달을 연다. 새 흐름은 모달 `연결 해제하기` 뒤에 `disconnect-eligibility`로 조건을 검사한다 (DIFF-2). 서버가 당일 등원도 `ATTENDANCE`로 알려주므로 앱의 홈 `checkInAt` 선차단을 남길지는 구현 때 정한다.
- 기존 코드는 서버 오류 `message`에 `등원`이 들어 있는지로 분기한다 (`isTodayAttendanceBlockedError`). 공통 오류 정책 5장은 `message` 파싱을 금지하고 `code`로 분기하라고 한다. 서버가 주는 `code`로 바꾼다: `GUARDIAN_SCHOOL_CONNECTION-409-2`(남은 이용권·예약), `SCHOOL_MEMBERSHIP-409-1`(당일 등원), `GUARDIAN_SCHOOL_CONNECTION-409-1`(이미 해제).
- 기존 모달은 `연결 해제하기` 처리 중 `ActionLoadingOverlay`로 중복 요청을 막고, 성공해야 모달을 닫는다. Figma는 `모달 닫은 후 해제 조건 검사`라서 모달을 닫은 뒤의 로딩 표시를 따로 정해야 한다.

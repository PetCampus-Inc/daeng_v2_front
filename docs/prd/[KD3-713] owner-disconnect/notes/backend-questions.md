# [KD3-713] 원장 연결 해제 — 백엔드 확인 요청

원장 앱 `원생 프로필`의 `연결해제`를 만드는 중인데, 이용권·예약이 남은 원생은 해제를 막아야 해서 현재 API로는 알 수 없는 것 4가지를 여쭤봅니다.

물어볼 사람: Minje Kang

---

## 1. 원생별 이용권 조회

- 대상 API
  - `GET /api/v0/owner/pets/{petId}/tickets` (원생별 이용권 조회, KD3-695, 아직 dev 병합 전)
- 현재: dev에 원장이 원생별 이용권을 조회하는 API가 없습니다. 원장 앱의 프로필 이용권은 임시 데이터로 보여주고 있습니다.
- 필요: 연결해제를 누르면 `사용 예정`·`사용 중`·`홀딩 중` 이용권이 남았는지 확인하고, 남았으면 안내 창에 이용권 이름, 잔여 횟수, 만료일(없으면 `만료 없음`)을 보여줘야 합니다. 만료된 이용권만 있으면 해제할 수 있습니다.
- 질문
  - 위 API는 언제 dev에 올라가나요?
  - 응답에 이용권 이름, 잔여 횟수, 만료일, 상태(사용 예정·사용 중·홀딩 중·만료)가 모두 들어가나요?

## 2. 원생별 예약 조회

- 대상 API
  - 원생별 예약 조회 API (아직 없음)
- 현재: dev에 원장이 원생별 예약을 조회하는 API가 없습니다.
- 필요: 끝나지 않은 예약(예약 확정·당일 등원 전·당일 재원 중)이 있으면 해제를 막고, 안내 창에 `{유치원} 예약`, 예약 날짜, 등원 예정 시간, 상태(`등원전`)를 보여줘야 합니다. 결석·하원 완료·예약일이 지난 등원 완료는 끝난 예약이라 해제를 막지 않습니다.
- 질문
  - 원생별 예약을 조회할 API를 만들 계획인가요?
  - 위 "끝난 예약" 기준을 서버가 걸러서 끝나지 않은 예약만 내려주나요?

## 3. 해제 API의 이용권·예약 조건 검사

- 대상 API
  - `POST /api/v0/owner/members/{memberId}/disconnect` (구성원 연결 해제)
- 현재: `OwnerMemberService.disconnectMember`는 연결 상태(`OWNER_MEMBER-400-2`)와 오늘 등원 기록(409)만 확인하고, 이용권·예약은 확인하지 않습니다.
- 필요: 확인 창을 띄운 사이 보호자가 예약하거나 이용권이 충전될 수 있어서, 해제를 처리하는 순간에도 이용권·예약이 남았는지 다시 확인해야 합니다. 남았다면 해제하지 않고 안내 창을 보여줍니다.
- 질문
  - 해제 API에 이용권·예약 조건 검사를 추가할 계획인가요?
  - 추가한다면 조건에 걸렸을 때 오류 코드와, 남은 이용권·예약 목록을 응답에 함께 주나요?
  - 계획이 없다면 앱이 1·2번 API로 직접 다시 확인해야 하는데 괜찮은가요?

## 4. 당일 등원 기록이 있는 원생의 해제

- 대상 API
  - `POST /api/v0/owner/members/{memberId}/disconnect` (구성원 연결 해제)
- 현재: 오늘 등원 기록(`CHECKED_IN`·`CHECKED_OUT`)이 있으면 409 `SCHOOL_MEMBERSHIP-409-1`로 해제를 막습니다.
- 필요: 기획 기준은 하원까지 마친 예약과 결석한 예약은 끝난 예약이라 해제할 수 있고, 같은 날 예약을 마친 뒤 해제하면 일과에 `연결해제` 태그를 보여주는 것입니다. 지금 서버 동작대로면 등원·하원을 마친 날에는 해제할 수 없습니다.
- 질문
  - 오늘 등원 기록으로 해제를 막는 조건을 기획 기준(하원 완료·결석이면 당일에도 해제 가능)으로 바꿀 계획인가요?

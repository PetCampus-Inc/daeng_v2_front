## 1. 개요

(문서 §1)

원장이 원생 프로필에서 원생의 연결을 해제할 수 있게 하되, 사용할 수 있는 이용권이나 끝나지 않은 예약이 있으면 해제를 막고 이유를 보여준다. 해제한 원생은 원장의 구성원 목록에서 빠지고 원장은 원생·보호자 프로필에 접근할 수 없으며, 보호자는 지난 이력을 계속 볼 수 있다.

- 현재(v3.0·v3.1): 해제를 막는 조건이 없다. 구성원 목록 카드의 `⋯` 메뉴에서 연결 해제를 누르고 확인 모달에서 바로 해제한다.
- v4.0: 이용권이 앱 안에서 관리되고 예약할 때 이용권이 차감된다. 한쪽에서 해제하면 양쪽 모두 해제된다. 원장 해제도 보호자 해제([KD3-663])와 같은 조건을 따른다.
- 문제: 이용권이 남은 원생을 해제하면 결제한 횟수를 쓸 곳이 사라지고, 잡혀 있던 예약은 처리할 곳이 없어진다.
- 목적
  - 사용할 수 있는 이용권이나 끝나지 않은 예약이 있으면 해제를 막아 결제한 횟수와 예약이 사라지지 않게 한다.
  - 해제할 수 없을 때 이유와 언제 해제할 수 있는지 알려준다.
  - 보호자 해제와 같은 조건·같은 결과를 갖게 한다.
  - 해제 후 처리(구성원 목록 제외, 원장 접근 차단, 보호자 이력 열람)는 v3.0 기준을 유지한다.

관련 문서(문서 §1.4): [KD3-34] 연결 상태 관리, [KD3-39] 원생/보호자 정보, [KD3-663] 보호자 연결 해제, [KD3-643] 충전 및 관리, [KD3-658] 보호자 등원예약, [KD3-682] 등하원 처리, 개인정보 처리방침(2026. 09. 01. 개정), 알림 정책, UX 라이팅.

## 2. 범위

### 2.1 만드는 것

(문서 §2.1)

- 원장 앱 `구성원` > `등록 원생` > `원생 프로필`
  - 연결 해제 진입(프로필 상단 오른쪽 `연결해제`)
  - 해제 가능 조건 검사와 해제 불가 안내
  - 해제 확인 모달과 해제 처리
- 해제 후 원장 쪽 처리(구성원 목록 제외, 프로필 접근 차단)
- 해제 알림(원장 해제 → 보호자)

(문서 §2.2)

| 제외 항목 | 제외 사유 | 후속 위치 |

| 원장용 해제(퇴원) 원생 조회 | v3.0과 같이 해제한 원생은 원장에게 보여주지 않는다. | 백로그 |

## 3. 사용자 흐름

(문서 §4)

1. `구성원` > `등록 원생` > `원생 프로필`에서 `연결해제`를 누른다.
2. 해제 가능 조건을 검사한다.
   - 이용권·예약이 남아 있으면 → 해제 불가 바텀시트. `확인` 또는 `X`를 누르면 원생 프로필로 돌아간다.
   - 모두 없으면 → 해제 확인 모달.
3. 해제 확인 모달
   - `닫기` → 원생 프로필로 돌아간다.
   - `해제하기` → 처리 직전에 조건을 다시 검사한다.
     - 조건이 바뀌었으면 → 해제 불가 바텀시트.
     - 통과하면 → 연결 해제 + 이력 저장 + 보호자 알림.
4. 해제가 끝나면 구성원 목록으로 이동하고(해제한 원생 제외) 토스트를 보여준다.

## 4. 공통 정책

### 4.1 해제 가능 조건

(문서 FR-03)

사용할 수 있는 이용권과 끝나지 않은 예약이 **모두 없을 때만** 해제할 수 있다. 기준은 보호자 연동해제 FR-03과 같다.

- 사용할 수 있는 이용권: 사용 예정·사용 중·홀딩 중. 만료된 이용권만 있거나 이용권이 없으면 해제할 수 있다.
- 끝난 예약: 결석(원장 결석·자동 결석), 하원 완료, 하원 처리를 하지 않은 예약일이 지난 등원 완료. 이 외의 예약(예약 확정·당일 등원 전·당일 재원 중)이 있으면 해제할 수 없다.
- 하원은 자동 처리하지 않지만, 예약일이 지나면 하원 처리 여부와 상관없이 끝난 예약으로 본다.
- 예약일이 지난 등원 전 예약은 다음 날 0시에 자동 결석되므로 해제를 막지 않는다([KD3-682] FR-09).
- 이 조건을 어디서 검사하는지(서버/클라이언트)와 조회 API는 (OQ-S1, OQ-S2, OQ-S3). 같은 날 등원·하원을 마친 원생을 해제할 수 있는지는 (OQ-S5).

### 4.2 해제 단위와 진입점

(문서 FR-01·FR-02)

- 원생 1마리씩 해제한다. 일괄 해제는 없다.
- 원생 프로필 상단 오른쪽 `연결해제` 버튼이 진입점 하나다. (Figma `36:16771` 상단 바)
- 구성원 목록 카드의 `⋯` 메뉴(v3.0)는 없앤다. (PRD 단독)

### 4.3 해제 처리

(문서 FR-07, Figma Description 36:17084)

- 연결 상태를 `연결 해제`로 바꾼다.
- 해제 주체(원장)·해제 일시·이전/이후 상태를 서비스 내부 상태 변경 이력으로 저장한다([KD3-34] KD-FR-CONN-COMMON-001). (PRD 단독)
- 성공하면 확인 모달을 닫고 구성원 목록으로 이동한 뒤 성공 토스트를 보여준다.
- 실패하면 기존 연결 상태와 원생 프로필 화면을 유지하고 실패 토스트를 보여준다.
- 처리 중에는 중복 요청을 막기 위해 확정 버튼(`해제하기`)을 비활성화한다.
- 보호자에게 알림을 보낸다(8장). 알림 발송에 실패해도 해제 결과는 유지한다([KD3-34] P-15). (PRD 단독)
- 해제를 확정하기 전까지 기존 원생 정보와 등록 상태를 유지한다.

### 4.4 처리 직전 재검사

(문서 FR-06) (PRD 단독)

- 확인 모달을 띄운 사이 보호자가 예약하거나 이용권이 충전되면 해제하지 않고 해제 불가 안내로 전환한다(보호자 연결 해제 FR-06과 같음).
- 해제할 수 없는 동안 기존 연결 관계를 유지하고, 이용권 상태가 바뀌면 해제 가능 여부를 다시 확인한다. (문서 FR-04, Figma Description)

### 4.5 해제 후 원장 쪽

(문서 FR-08, FR-10, 상태 정의)

- v3.0 기준을 유지한다([KD3-34], [KD3-39] P-02).
- 해제한 원생은 구성원 목록에서 빠진다.
- 원생·보호자 프로필(이용 정보·보호자 정보·등하원 기록)에 진입할 수 없다. 알림이나 열어 둔 화면 등으로 진입하면 연결 상태를 확인해 공통 오류 화면을 보여준다([KD3-39] E-03). (PRD 단독, 문구는 7.4)
- 출결 이력은 유지한다. 등원 이력이 있으면 일과에 `연결해제` 태그를 표시한다. (문서 FR-08과 Figma Description이 같음)
- 원장용 해제 원생 조회·해제 내역 조회는 제공하지 않는다. (PRD 단독)
- 보호자가 먼저 해제한 경우도 같다. (PRD 단독)
- 끝나지 않은 예약이 있으면 해제할 수 없으므로, 당일 해제는 그날 예약을 등원·결석으로 마친 뒤에만 생긴다. 그날 해제된 원생은 일과에서 처리할 수 없다. (PRD 단독, 서버 동작과 다름: OQ-S5)

### 4.6 해제 후 보호자

(문서 FR-09) (PRD 단독)

- v3.0 기준을 유지한다([KD3-34] P-10·P-11).
- 지난 알림장·앨범·등하원 기록, 이용권 이력, 유치원 연결 이력을 읽기 전용으로 볼 수 있다. 수정·새 예약은 할 수 없다.
- 화면 기준은 보호자 연동해제 PRD FR-07을 따른다. 이 문서의 구현 범위가 아니다.

### 4.7 재연결

(문서 FR-11) (PRD 단독)

- 해제한 원생이 다시 연결 신청해 승인되면 새 연결을 만든다. 기존 연결을 되살리지 않는다([KD3-34] P-12).
- 원생 프로필의 `연결 내역`에는 현재 연결 기간만 표시한다. 해제 전 지난 연결 기간과 등원 횟수는 원장에게 보여주지 않는다.

### 4.8 용어

(문서 §8.1) (PRD 단독)

- 화면 문구는 `연결 해제`를 쓴다. 상단 버튼과 일과 태그만 `연결해제`로 붙여 쓴다. `연동`은 쓰지 않는다(UX 라이팅 금지 표현).
- 오류는 [오류 정책], 로딩·중복 요청은 [공통 로딩 정책]을 따른다. 이미 해제된 원생은 이미 처리된 요청 기준을 따른다.

## 7. 화면 명세

화면 순서는 Figma 흐름(프로필 → 확인 모달 → 토스트 / 해제 불가 시트)을 따른다.

### 7.1 S-01 원생 프로필 (기본)

(문서 §8 S-01, Figma `36:16771`)

- 상단 바: 뒤로, `원생 프로필`, 오른쪽 `연결해제`
- 프로필, 탭(`이용 정보` · `보호자 정보` · `등하원 기록`)
- `연결해제`를 누르면 조건을 검사해 S-02 또는 S-03을 보여준다.
- 상단 버튼 문구는 `연결해제`(붙여 씀).
- 조건을 조회하는 동안에는 `연결해제` 버튼만 비활성화하고 별도 로딩 표시는 없다. 조회에 실패하면 S-01에 머물며 토스트 `연결 해제를 완료하지 못했어요`를 보여준다. (2026-11-09 사용자 결정)

### 7.2 S-02 해제 불가 바텀시트

공통(문서 §8 S-02, Figma Description 36:17084)

- 배경 Dim, 제목, 오른쪽 위 `X`, 본문, 목록, `확인` 버튼 (X 표시는 OQ-F4)
- `확인`(Orange Filled)이나 오른쪽 위 `X`를 누르면 시트를 닫고 원생 프로필을 유지한다.
- 제목: `아직 연결을 해제할 수 없어요.` (DIFF-2)
- 해제할 수 없는 동안 원생과 유치원의 기존 연결 관계를 유지한다.

이용권이 남은 경우(Figma `36:16945`)

- 본문: `사용할 수 있는 이용권이 아직 남아 있어요.` 줄바꿈 `이용권을 삭제하거나 만료된 뒤 해제할 수 있어요.`
- 목록 항목: `{이용권 이름}`, `{n}회 남음`, `YYYY.MM.DD까지` 또는 `만료 없음`
- 잔여 횟수(`6회 남음`)는 주황색으로 강조한다.
- 이용권이 여러 개면 목록 영역 안에서 스크롤한다. (Figma `36:16945`는 4개 항목과 스크롤 막대를 보여준다.)
- 이용권을 다 쓰거나 삭제하거나 만료된 뒤에 해제할 수 있다.

예약이 남은 경우(Figma `36:17003`)

- 본문: `완료되지 않은 예약이 남아 있어요.` 줄바꿈 `예약한 날이 지나면 해제할 수 있어요.` (Figma `36:16885`는 지난 시안이라 따르지 않는다. 2026-11-09 사용자 결정)
- 목록 항목: `{유치원} 예약`, `YYYY.MM.DD 오후 h:mm 등원 예정`, 오른쪽 `등원전`(주황색, Figma 단독)
- 원장은 예약을 취소할 수 없으므로 예약일이 지나 예약이 끝날 때까지 해제할 수 없다. 보호자가 예약을 취소하면 그 전에 해제할 수 있다. (PRD 단독)

이용권과 예약이 모두 남은 경우

- 두 목록을 함께 표시한다. (PRD 단독)
- 본문은 이용권이 남은 경우의 문구를 쓴다: `사용할 수 있는 이용권이 아직 남아 있어요.` 줄바꿈 `이용권을 삭제하거나 만료된 뒤 해제할 수 있어요.` (2026-11-09 사용자 결정)
- 목록 순서는 예약 항목 다음에 이용권 항목이다. (2026-11-09 사용자 결정. Figma `36:17003`의 숨겨진 두 번째 항목 순서와 같다.)

### 7.4 S-04 원생 프로필 접근 불가

(문서 §8 S-04) (PRD 단독)

- 해제된 원생의 프로필에 진입하려 할 때 공통 오류 화면(full-page)을 보여준다([KD3-39] E-03).
- 공통 오류 화면(`PageError`, 전면 `overlay` 배치)의 기본 문구를 그대로 쓴다. (2026-11-09 사용자 결정)
  - 제목: `정보를 불러오지 못했어요`
  - 설명: `잠시 후 다시 시도해 주세요.`
  - 버튼: `다시 시도하기` (누르면 화면을 새로고침한다)
- `[KD3-39] M-06` 문구는 이 문서의 원본에 없고 확인하지 못해 쓰지 않는다.

### 7.5 구성원 목록

- 해제한 원생은 목록에 나오지 않는다. 카드의 `⋯` 메뉴는 없앤다. (4.2, 4.5)
- 보호자나 다른 기기에서 먼저 해제해 이 기기의 목록이 오래된 경우, 그 원생 카드를 눌렀을 때 이미 해제된 것을 알게 되면 프로필로 들어가지 않고 구성원 목록 화면에 머문 채 화면 하단에 토스트 `이미 연결을 해제한 원생이에요.`를 보여준다. (2026-11-09 사용자 결정. 문구는 Figma 구성원 목록 화면 `36:16636`과 같다.)
- 이때 오래된 카드가 목록에 계속 남지 않도록 목록을 다시 불러온다. (내 추론)
- 알림이나 열어 둔 프로필 화면에서 해제된 원생의 프로필로 들어오는 경우는 7.4의 공통 오류 화면을 쓴다.
- 해제된 것은 원생 프로필 조회가 403 `PET-403-1`(`PET_NOT_AUTHORIZED`)로 실패하는 것으로 알아낸다. 이 코드는 해제된 원생뿐 아니라 이 유치원에 연결되지 않은 원생에게도 나오지만, 이 화면에서는 해제된 경우로 본다. (백엔드 코드 확인 2026-11-09)
- Figma 구성원 목록 화면(`36:16607`)은 이번 범위의 변경 대상이 아니며 해제 전·후 토스트를 보여주는 배경으로만 쓰였다. (Figma 단독)

## 11. 구현할 때 놓치기 쉬운 점

이 장은 원본 요구사항이 아니라 코드베이스를 확인하며 남긴 구현 메모다. (확인일 2026-11-09, 경로는 저장소 루트 기준)

- 진입 버튼은 이미 있다. `apps/knockdog/src/views/owner/member-profile/ui/OwnerMemberProfilePage.tsx`의 `OwnerMemberProfileDisconnectButton`이 `@knockdog/ui`의 `DisconnectButton`(기본 문구 `연결해제`, `packages/ui/src/components/disconnect-button/DisconnectButton.tsx`)을 헤더 오른쪽에 쓴다. 지금은 누르면 바로 확인 모달이 뜨고 조건 검사는 없다.
- 해제 확인 모달·처리 훅이 이미 있다. `apps/knockdog/src/views/owner/member-profile/model/useOwnerMemberProfileDisconnect.tsx`와 `apps/knockdog/src/views/owner/member-profile/ui/OwnerMemberProfileDisconnectDialog.tsx`. 모달은 처리 중 중복 요청 방지(`isSubmitting`)가 이미 있다.
- 지금 문구는 v3.0이다. `apps/knockdog/src/views/owner/member-profile/config/ownerMemberProfileContent.ts`의 `disconnectDialog`(`유치원 연결을 해제하시겠어요?`, 버튼 `닫기`·`연결 해제하기`), `disconnectSuccessToastSuffix`(`의 유치원 연결을 해제했어요`), `disconnectFailToast`(`일시적 오류로 요청을 완료하지 못했어요`). 이번 문구와 다르다. 강아지 이름 말줄임은 `nameMaxLength: 8`이 이미 있다.
- 해제 후 이동은 이미 `navigateToTab('/owner/members', undefined, 'owner')`이고, 성공 뒤 이동·토스트 오류는 해제 완료로 간주한다(훅 주석).
- 해제 API는 `apps/knockdog/src/entities/owner-member/api/ownerMember.ts`의 `postDisconnectOwnerMember` → `POST owner/members/{memberId}/disconnect`. `memberId`는 구성원 목록에서 `petId`로 찾는다(`findOwnerMemberByPetId`). 성공 시 구성원·일과·홈·알림함·원생 프로필 캐시를 갱신한다(`apps/knockdog/src/entities/owner-member/api/useOwnerMemberMutation.ts`의 `useOwnerMemberDisconnectMutation`).
- 보호자·알림 발송은 서버 책임이다(`useOwnerMemberProfileDisconnect.tsx` 주석 "알림은 서버 발송"). 클라이언트가 N-01을 보내지 않는다.

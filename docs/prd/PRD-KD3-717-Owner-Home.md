## 1. 개요

오늘의 출결과 알림장 업무 현황을 홈에서 확인하고, 미등원 원생 처리·새 원생 신청·소식·이용권 화면으로 진입한다.
근거: Description §1~7 (`12192:210472`), 신규 홈 `12192:210475`.

## 2. 범위

### 2.1 만드는 것

- 홈 상단 구조, 날짜·현재 재원 수 안내, 출결 요약, 미등원 원생 안내, 신청 배너
- 알림장·소식 관리·이용권 확인 업무 카드
- 하단 `홈 / 일과 / 앨범 / 구성원 / 마이` 및 홈 활성 표시
- 시안에 연결된 화면의 진입 상태: 구성원 신청, 구성원 만료예정 필터, 일과 등원처리·발송전, 유치원 소식 (지각 필터 ON)
- 유치원 소식의 상단 내비게이션 좌측 정렬 변경은 Figma 표제에 명시됨 (`12192:210826`)

### 2.2 범위 경계

- Description §5c는 `이용권 관련 상세 기능은 기존 이용권 관리 정책 적용.`이라고 명시한다. 이용권 상세 기능을 이 문서에서 새로 정의하지 않는다.
- Description §7은 `게시물 작성 및 수정 기능은 유치원 소식 관리 정책 적용.`이라고 명시한다. 작성·수정 상세 정책을 새로 정의하지 않는다.
- 기존 홈 `12192:210797`의 `연결 관리 / 앨범 등록 / 유치원 소식 / 보호자 초대`를 신규 홈의 필수 요소로 이월하지 않는다.
- OQ-F11 확정: 홈과 지정 탭·필터 진입, 소식 헤더 좌측 정렬까지만 변경한다. 일과·구성원의 전체 UI 및 상세 업무를 재구현하지 않는다. 기존 소식 목록·신청 목록·QR·알림함 API를 홈의 신규 호출로 확대하지 않는다.

### 2.3 기획자 확인된 보충 요구사항

별도 Notion은 없다. 본 세션 사용자 답변으로 확정한 보충 정책은 §10의 확정된 질문에 보존했다. 기획자 이름·서버 개발자 답변을 추정하지 않는다.

## 4. 공통 정책

- 로고 아래 유치원명을 유지한다 (OQ-F1). 우측 QR·종 아이콘, 하단 `홈 / 일과 / 앨범 / 구성원 / 마이`와 Safe Area·세로 스크롤은 시안을 따른다.
- 별도 등원처리 버튼은 만들지 않는다 (OQ-F2).
- 오늘은 `Asia/Seoul` 기준이며 홈과 일과의 집계 정의는 같다.
- 기획자 최종 답변(OQ-F4): 홈의 `등원 시간이 지난 강아지` 영역은 **지각 원생만** 표시한다. 지각 대상과 인원수는 서버가 판단하고 프론트는 서버가 제공하는 결과를 표시한다(2026-11-13 사용자 결정). 마지막 확인한 API-1은 미등원 전체를 반환한다. 2026-11-13 사용자 전달에 따라 서버가 기획에 맞춰 수정해 지각 전용 목록·인원수를 제공하기로 확정했다(OQ-S5). 프론트에서 기존 일과의 예약 +30분 기준을 임의 적용하지 않는다.
- 서버가 제공한 지각 원생이 0명이면 안내 영역 전체를 숨긴다. 1명 이상이면 기본 접힘이며 펼치면 지각 원생 전원을 예약 시각 순으로 표시하고 홈 콘텐츠 스크롤을 사용한다. 표시 인원수는 서버의 지각 집계를 사용한다. 현재 미등원 count를 지각 수로 간주하지 않으며 서버의 기획 반영 약속으로 OQ-S5는 해결됐다.
- 홈 진입·홈 복귀·앱 foreground 복귀·한국 시간 자정에 갱신한다. 기존 PullToRefresh도 유지한다 (OQ-F10).
- 각 데이터 영역은 로딩·실패를 구분하고 성공한 영역은 유지한다. 같은 API-1을 사용하는 영역은 요청 결과를 공유하며 영역별 별도 API를 만들지 않는다 (OQ-F9).
- 알림장 집계는 오늘 등원한 강아지(하원 포함) 중 미발송 건이다. 미작성·임시저장은 포함하고 미등원·결석은 제외한다 (OQ-F6).

## 7. 화면 명세

### 7.1 기존 홈 — 비교 자료

표제 `기존 홈` (`12192:210812`), 화면 `12192:210797`.
기존 카드의 `재원 중 / 오늘 등원 / 오늘 하원`, `발송 전 알림장 … 이 있어요`, 4개 바로가기를 신규 홈 명세로 혼합하지 않는다.

### 7.2 신규 홈

표제 `신규 홈` (`12192:210814`), 화면 `12192:210475`, 390×844 시안.

1. 상단: 로고와 그 아래 유치원명을 유지한다. QR은 기존 초대 시트, 종 아이콘은 알림함으로 연결하며 미읽음 원장 알림에만 점을 표시한다 (OQ-F1·F3·F8)
2. 흰색 라운드 카드: `6월 18일 화요일`, `지금 유치원에\n12 마리 강아지가 놀고 있어요!`; 원생 수 부분 주황 강조
3. 카드 안 연한 배경의 지각 원생 안내: `등원 시간이 지난 강아지`, `2 마리`, 아래 방향 화살표 (OQ-F4)
4. `등원 완료 / 결석 확정 / 하원 완료` 순으로 수치와 라벨 표시
5. 하단 업무 카드: 좌측 큰 `알림장` 카드, 우측 상단 `소식 관리`, 우측 하단 `이용권 확인`
6. 시안 원문: `8 건 작성 필요`, `소식을 업로드 할 수 있어요`, `만료 예정인 이용권이 2건 있어요`
7. 하단 내비게이션: 홈 활성, Safe Area 고정. 카드가 길어져도 콘텐츠 스크롤 가능

별도 `등원처리` 버튼은 제거하며, 알림장 카드는 전체 클릭으로 이동하고 별도 `알림장 확인` 버튼을 추가하지 않는다 (OQ-F2·F6).

### 7.3 홈 — 원생 신청 도착 시

표제 `홈- 원생 신청 도착시` (`12192:210816`), 화면 `12192:210687`, 390×932.
상단과 현황 카드 사이에 둥근 흰색 배너, 알림 아이콘·문구·우측 X. 이미지 원문은 `새로운 원생 신청이 있어요!`.
Description §3 원문 `새로운 등원 신청이 있어요!`과의 차이는 OQ-F5에서 확인하여 시안 문구 `새로운 원생 신청이 있어요!`로 확정했다.
배너 클릭은 구성원 신청 탭, X는 API-8로 닫기이며 클릭 전파를 구분한다. API-1의 `bannerVisible`을 따르고 닫을 때 본 `latestId`를 전달한다. 계정 전체에서 앱 재시작·기기 변경 후에도 유지하며 새 신청이면 재노출한다. 기존의 같은 계정·기기 유지 답변은 이후 계정 전체 적용 선택으로 변경됐다.

### 7.4 홈 — 등원 시간이 지난 강아지

기존 Figma 표제 `홈-등원하지 않은 강아지` (`12192:210818`), 화면 `12192:210576`, 390×952. 화면 안내 문구는 2026-11-13 사용자 첨부 수정 시안의 `등원 시간이 지난 강아지`를 적용한다.
지각 원생 안내에 위 방향 화살표, 원형 프로필 자리와 `초롱이`·`초록이` 목록이 펼쳐져 있다.
문구가 있는 상단 행은 펼침·접힘, 원생을 포함한 펼친 영역 전체는 페이지 이동이다. 개별 원생 ID로 도착 목록을 한정하지 않는다. 지각 원생만 예약 시각 순 전체 표시하며 지각 0명이면 전체 영역을 숨긴다 (OQ-F4).

### 7.5 펼친 지각 원생 영역 클릭 시 — 일과 등원처리·지각 필터 ON

표제 `등원 X 강아지 클릭시` (`12192:210820`), 화면 `12402:206832`.
일과 날짜·오늘 버튼, 출결 요약, `등원처리` 활성 탭, 검색, `지각` 표시가 있다.
원생 행에 `9:00 등원 예정`, `지각`, `결석처리 / 등원처리` 버튼. 처리 후 홈 미등원 수가 자동 갱신되어야 한다 (§4).
기획자 최종 확인: 홈에는 지각 원생만 표시하며 원생 클릭 시 오늘 일과의 `등원처리` 탭에 지각 필터 ON으로 이동한다. 상단 행 펼침·접힘과 펼친 영역 클릭 경계는 유지하고, 기존 `lateOnly=true` 진입 처리를 재사용한다.

### 7.6 알림장 클릭 시 — 일과 등원목록

표제 `알림장 클릭시` (`12192:210822`), 화면 `12402:207516`.
일과의 `등원목록` 탭 활성, `전체 10 / 재원중 1 / 발송전 1` 중 `발송전` 선택.
원생 카드에는 등하원 시각, `하원완료`, `알림장 작성하기`, `하원취소`가 표시된다.
홈 카드 전체 클릭으로 위 탭·필터에 진입한다. 오늘 등원한 강아지(하원 포함)의 미작성·임시저장·미발송을 포함하고 미등원·결석은 제외한다. 0건에도 `0건 작성 필요`와 클릭 동작을 유지한다 (OQ-F6). 숫자는 예시다.

### 7.7 이용권 확인 클릭 시 — 구성원

표제 `이용권 확인 클릭시` (`12192:210824`), 화면 `12192:210970`.
구성원 `등록 원생` 탭과 `만료예정 2` 필터가 선택되어 있다.
`전체 22 / 만료예정 2 / 만료 3`, 원생 이름, 보호자·연락처, `1회 남음` 또는 `D-3`, 이용권 잔여 안내 표시.
OQ-F7 확정: 기존 구성원 정책과 API-4 `counts.expiring`을 재사용한다. 원생별 대표 이용권 기준 만료까지 3일 이하(D-0 포함) 또는 잔여 1회이며, 여러 이용권을 원생 수에 중복 집계하지 않는다. 0명은 `만료 예정인 이용권이 없어요`로 표시하고 같은 필터에 이동한다. 홈에서 임계값을 별도 계산하지 않는다.

### 7.8 소식 관리 클릭 시 — 유치원 소식

표제 원문 `소식 관리 클릭시 (기존 유치원 소식탭에서 상단 네비만 좌측 정렬)` (`12192:210826`).

- 목록 `12192:211145`: 뒤로가기와 좌측 정렬 `유치원 소식`, 우측 검색, 게시물 목록과 우하단 `+`
- 빈 상태 `12192:211171`: 뒤로가기·좌측 정렬 제목, 중앙 일러스트, `아직 올린 소식이 없어요`, `소식을 올려 보호자에게 알려 보세요.`, 우하단 `+`
- `+` 선택 시 새로운 게시물 작성 화면 (§7). 작성·수정은 기존 소식 관리 정책

### 7.9 상단 알람 멘트 클릭 시 — 구성원 신청

표제 `상단 알람 멘트 클릭시` (`12192:210828`), 화면 `12192:210996`.
구성원 `신청` 탭 활성, `강아지수 5`, `최신순`, 신청 원생 행에 `거절 / 승인`.
이는 Description §3의 배너 경로와 일치한다. 상단 종 아이콘은 기존 알림함으로 이동하며, 신청 배너와 구분한다 (OQ-F3).

## 8. 알림

- 신청 배너 문구는 `새로운 원생 신청이 있어요!`, 노출은 API-1 `pendingApprovals.bannerVisible` 기준이다.
- X는 API-8로 계정 전체에서 닫힘을 저장하고 더 새로운 신청이 들어오면 재노출한다 (OQ-F5).
- 종 아이콘은 기존 알림함으로 이동하고 미읽음 원장 알림이 있을 때만 주황 점을 표시한다 (OQ-F3).
- Figma에 갱신 성공·실패 Toast 원문은 없다. 홈 실패 안내는 OQ-F9의 확정 문구를 사용한다.

### API-1 지각 데이터 결정 (OQ-S5 해결)

- 2026-11-13 사용자 전달 원문: “서버가 기획에 맞춰 수정해주기로 했다.”
- 서버가 기획대로 홈의 지각 원생 목록·인원수를 제공하기로 확정했다. 프론트는 서버 결과를 표시하며 지각 판정·집계를 대신 구현하지 않는다.
- 답변과 결정은 §10의 확정된 질문에 이관했다. 추가 질문·완료 통보 대기·계약 재확인을 테스트 목록 작성 조건으로 두지 않는다.

### 계약 확인 결과

- 2026-11-13 개발 Swagger와 remote dev 최신 SHA의 홈·구성원·배너 닫기 요청·응답을 대조했고 차이를 발견하지 않았다. 요청·응답 형태의 일치와 별개로 마지막 조회 당시 홈 지각 전용 요구와 서버 반환 대상 사이에 불일치가 있었으며, 서버가 기획에 맞춰 수정하기로 답변해 OQ-S5는 해결됐다.
- 홈 미등원 목록은 API-1 `notCheckedInPets`로 제공된다. 일과의 기존 `GET /api/v0/attendance-checkinouts/candidates` 조회를 홈의 추가 호출로 넣지 않는다. 해당 일과 계약은 `date`만 받으며 미등원·등원·하원·결석을 모두 반환하므로 `totalCount`는 미등원 수가 아니다.

### 프런트엔드 제약 근거

- 기존 2026-11-12 조사 SHA `47de79c3b03a76c5015bb7a5187443809d03532e`는 과거 조사 기준이며 현재 HEAD라는 뜻이 아니다.
- `apps/knockdog/src/views/owner-home-page/ui/OwnerHomePage.tsx`: 기존 알림함 이동·PullToRefresh 재사용 근거.
- `apps/knockdog/src/views/owner-home-page/model/useOwnerHomePage.ts`: 네이티브 탭 이동·웹 경로 대체. 오늘 등원처리 탭·지각 ON 상태를 네이티브·웹 양쪽 경로에서 보장해야 함.
